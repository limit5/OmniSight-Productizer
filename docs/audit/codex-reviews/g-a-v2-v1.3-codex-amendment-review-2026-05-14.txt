## §2. New issues introduced (Q-2)

1. P1 — SD-1 evidence commands are not copy-pasteable from this review branch (§0.1 lines 65-84; schema lines 176-184). Running them as written produced missing-file exits for the parent spec, phase-31g spec, and `backend/governance_engine/`. This is the only amendment that risks reintroducing a P0-shaped issue because it weakens the validator’s own evidence format. Concrete fix: replace working-tree paths with `git show HEAD:<path>` / `git show refs/remotes/gerrit/develop:<path>` commands and actual result snippets.

2. P1 — New `v2-⑤-AutoRedeploy` is undersized as tier:S (line 438). It changes prod compose pull policy or adds a watcher/cron that recreates prod services, and it is operator-prepare-only with runtime consequences. Concrete fix: make it tier:M, or split into S spec + M operator-window implementation.

3. P1 — The two new v1.3 tickets lack boundary blocks. `v2-⑤-AutoRedeploy` line 438 needs destructive/lifecycle boundaries; `v2-⑦-Reproduce-401` line 459 touches auth/security discovery and CI integration. Concrete fix: add §3.0.5 blocks for both before filing.

4. P2 — Stale local counts/headings remain. Family ⑤ says “Tickets (7)” at line 427 but has 8 rows; Family ⑦ says “Tickets (6)” at line 454 but has 7 rows; Family ⑩ says “Tickets (16)” at line 543 but has 17 rows. Effort estimates at lines 636-637 still say 7 and 6 tickets for ⑤/⑦. Concrete fix: update headings and estimates to match §5 totals.

5. P2 — Family ⑩ is directionally faithful to my self-audit, but several implementation tickets are tier:S despite cross-runner/DB/coordination blast radius (lines 549-552, 558-559). This is not a filing blocker because §5 counts Cutover/Integration as M and boundaries cover `v2-⑩-2d`/RescueCLI, but v1.4 should consider making `v2-⑩-1bc` M due to table + alembic + integration scope.

P2 — Boundary schema mostly coheres with G.A-v0/G.A-v1 fields, but `required_area_labels` is introduced as a nested boundary field while the SOP path-to-area rule expects labels as filing metadata. Concrete fix: state that `required_area_labels` must be materialized as JIRA labels at filing time, not only stored in the YAML block.

7. P2 — Cross-reference check found no remaining `v2-⑨-2a` typo. AlertBridge, `v2-⑤-AutoRedeploy`, and `v2-⑦-Reproduce-401` are consistently referenced in §5/§6. The unresolved references are external placeholders (`31.C`, `31.G`, `G.A-v0-A7`) rather than renamed local IDs.
