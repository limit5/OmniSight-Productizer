# Audit brief — v0.6.2 prod+staging deploy fragility (2026-05-26)

**Origin:** OP-1717 (tier:X, prod-compose-context) widened by the operator after the v0.6.2 cut. The
v0.6.2 deploy *succeeded* (prod live, block UI verified) but hit ~12 snags — the operator's read:
"環境設定 / 基礎建設穩定性不夠,非常脆弱,稍微碰一下就會壞掉." This brief captures the **lived
evidence** (run 2026-05-26) to anchor a 3-way disprove-audit. Goal: deploy prod+staging goes as
**smoothly as expected** — clean context, no implicit env/landmines, documented + ideally single-command.

Builds on (does NOT duplicate) the 2026-05-25 deploy-pipeline deep audit (OP-1709, 36 findings).
Those were mostly *gating/enforcement* gaps; THIS is *operability/fragility* of the human deploy path.

## Auditor instructions (Stage 2)
For EACH finding below: (1) try to **DISPROVE** it (is it real? still real on develop-tip? mis-stated?);
(2) rate **blast radius** (what breaks if mis-fixed: prod uptime / release correctness / runner / staging);
(3) estimate **workload** (S/M/L) + **side-effects** of the fix; (4) flag **goal-drift risk** if handed to a
runner; (5) propose the **smallest safe fix**. Cite file:line. Two-sided: don't rubber-stamp, don't bulldoze
live/tested infra ([[feedback_remove_dead_x_verify_liveness]]).

## Findings (lived evidence from the v0.6.2 cut→deploy)

**F1 — cosign PATH fragility (promote).** `promote_image_bundle.py` → `verify_image_signature.sh` needs
`cosign` (at `/home/user/bin/cosign`). Running promote with `env -i PATH=/usr/bin:/bin:/usr/local/bin`
(the clean-env habit used to dodge pydantic `extra_forbidden`) DROPPED cosign → `FAIL: cosign not installed`
mid-promote (after a partial retag). The pydantic issue is now handled by `OMNISIGHT_TOOLING_TOLERATE_EXTRA_ENV=1`,
so the clean-env habit is both unnecessary AND harmful. Impact: promote aborts. Fix dir: drop clean-env from
the runbook; document the normal-env + tolerate-flag invocation; or have the script self-locate cosign.

**F2 — RT-20 `--tag` UX trap (deploy-prod).** `deploy-prod.sh --tag=v0.6.2` is REJECTED by `check_deploy_ref`
("git-tag deploys not permitted, RT-20 image-tag-only — deploy by digest"). BUT `deploy-prod.sh` usage
examples AND the release-train runbook §6 SHOW `--tag=vX.Y.Z`. Operator hit the rejection live, had to switch to
`--backend-digest=… --frontend-digest=…`. Doc/tool contradiction. Fix dir: reconcile — either accept a promoted
*image* tag (resolve→digest) or fix all docs/examples to digest-only + a clear error pointing to the digest form.

**F3 — sealed bundle unfetchable + manual reconstruction.** Promote needs the sealed bundle (real digests,
bridge stripped). The CI seal artifact is NOT fetchable (claude-bot 404s on GitLab pipeline read). The baked
`/app/bundle.json` has ZERO digests by design. Operator had to: extract baked bundle → inject real digests
(from `imagetools inspect`) → `del bridge` → hand to promote. Fragile, undocumented, error-prone. Fix dir: a
helper that builds the promote bundle from the running/CR image (digests + bundle_id from labels), OR make the
sealed CI artifact fetchable by the release operator.

**F4 — DLP-scan-from-worktree (FIXED OP-1731).** backup DLP scan resolved PG→127.0.0.1 from a worktree →
shredded the dump. Confirm the fix is complete + that the sanctioned backup now works from a worktree.

**F5 — persistence / stale-checkout landmine (OP-1717 core).** `omnisight-compose-prod.service`
`WorkingDirectory=/home/user/work/sora/OmniSight-Productizer` = main checkout **94 behind develop + 27 dirty**.
The deploy ran from a `/tmp` worktree (vanishes on reboot). The main `.env` had `OMNISIGHT_IMAGE_TAG=sha256:dfa…`
— a **digest-as-tag**, INVALID for the tag-based main compose (`:${OMNISIGHT_IMAGE_TAG}`) → a reboot would
have failed/reverted. Operator manually set `OMNISIGHT_IMAGE_TAG=v0.6.2` to fix. Blast radius: HIGH (a reboot
could bring prod up wrong/down). Fix dir: clean develop/release-tracking checkout for prod+staging compose units;
canonical `.env` consistency; verify `compose config` resolves post-deploy.

**F6 — backup not wired into deploy + passphrase hunt.** `deploy-prod.sh` does NOT call `backup_prod_db.sh`
(no pg_dump step) — the "pg_dump first" hard rule is a SEPARATE manual step, easy to skip. The backup passphrase
is NOT in `.env`; it's in `~/.config/omnisight/backup.env` (operator had to find it). Fix dir: wire a mandatory
pre-deploy backup gate into deploy-prod.sh (fail-closed if no fresh backup), with a documented passphrase source.

**F7 — deploy-prod.sh worktree assumptions.** Step 1 does `git fetch <remote> --tags` (a git-tag concept under
an image-tag-only train); `.env` must be in cwd; `COMPOSE_PROJECT_NAME=omnisight-productizer` must be set
manually to attach the live stack from a worktree. Implicit knowledge. Fix dir: make the worktree/project
context explicit + documented, or remove the git-fetch step for digest deploys.

**F8 — promote-ledger stranded (FIXED OP-1732).** Confirm the helper + runbook step close it.

**F9 — dual-checkout drift + no confirmed sync (#15).** prod/staging compose units → main checkout; gate/bridge
units → `/home/user/sora-bridge` (currently develop-tip+clean). What KEEPS sora-bridge at develop-tip? No
confirmed puller → silent drift risk (the same class as F5). Fix dir: one known-good checkout per role with an
explicit, monitored sync (or pin) mechanism.

**F10 — candidate pipeline = operator-only.** Every release needs an operator to trigger the candidate build
(`glab ci run`; claude-bot 401s on pipeline create AND 404s on read). Not self-serve; couples release cadence to
the operator. Fix dir: a release-bot credential / a sanctioned trigger path (lower priority — security tradeoff).

**F11 — deployment-audit.sh alembic check buggy (#21, prior audit).** Compares prod head vs the *local stale
checkout* → false alembic verdicts when the checkout is behind (which it was, 94). Tie to F5/F9 (stale context).

**F12 — no correct single-command release path.** The "sanctioned" orchestrator (POST /api/v1/prod/deploy, path B)
is stubbed/unwired (OP-1690). The real path is ~10 manual steps (build→gate→bundle→promote→backup→deploy→flag→
persist) with implicit env/context, spread across scripts + a runbook that contradicts the tools (F2). This is the
root of "breaks at the slightest touch." Fix dir: a thin, correct release driver that chains the verified steps
with fail-closed gates, OR a hardened runbook with every implicit step made explicit + a preflight check.
